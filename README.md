# 基于 RNN 和 LSTM 的锂电池 SOC 估计

本项目用电压、电流和电池温度估计 Panasonic 18650PF 电芯的荷电状态（SOC）。RNN 和 LSTM 都在 25 ℃ 的 UDDS 工况上训练，在 US06 上比较模型配置，并用 LA92 复评跨工况表现。

**RNN V2 在 US06 上的平均误差最低**，MAE 为 **3.09 个百分点**。**LSTM V6 在 LA92 上的 MAE 为 0.81 个百分点**，同时在 US06 上具有更低的最大绝对误差。完整调参结果见下方表格及 [原始日志](logs/)。

## 数据与预处理

| 用途 | 25 ℃ 工况 | 原始文件 |
| --- | --- | --- |
| 训练 | UDDS | `03-21-17_00.29 25degC_UDDS_Pan18650PF.mat` |
| 参数比较 | US06 | `03-20-17_01.43 25degC_US06_Pan18650PF.mat` |
| 两种模型的额外工况复评 | LA92 | `03-21-17_09.38 25degC_LA92_Pan18650PF.mat` |

原始数据由 Phillip Kollmeyer 发布。将解压后的数据放入项目根目录的 `datasets/`，脚本会按文件名递归查找相应的 `.mat` 文件。该目录通过 `.gitignore` 管理，克隆项目后需要另行准备数据。 [Panasonic 18650PF 原始数据集](https://data.mendeley.com/datasets/wykht8y7tg/1)

1. **读取数据和计算参考 SOC。** 从 `.mat` 的 `meas` 读取 `Time`、`Voltage`、`Current`、`Battery_Temp_degC` 和 `Ah`，去掉重复行。假设文件开始时为满电，按 `SOC(t) = 1 + (Ah(t) - Ah(0)) / 2.9` 计算标签，配置容量为 `2.9 Ah`。例如 US06 的 `Ah` 从 `0` 变到 `-2.58596`，按这个口径末尾 SOC 约为 `10.83%`。
2. **标准化输入。** 按电压、电流、温度的顺序组织三列特征，并使用 UDDS 的均值和标准差做 Z-score 标准化。评估时从权重文件读取这组统计量，用于处理 US06 或 LA92。SOC 标签以 0–1 比例参与计算。
3. **构造滑动窗口。** 每次向后移动一个采样点。去重后有 `N` 个采样点时，长度为 `W` 的完整窗口共有 `N - W + 1` 个。采样间隔约为 0.1 秒，所以 100 点约覆盖 10 秒，300 点约覆盖 30 秒。 [数据加载与窗口构造](src/dataset.py)

## 训练与评估

[模型定义](src/model.py) 分别使用 PyTorch 的 `nn.RNN` 和 `nn.LSTM`，再用全连接层把每个时间步的隐藏状态映射为一个 SOC 预测。训练与评估都取**窗口最后一个时间点**的 SOC，与同一时刻的参考值比较。

- [训练脚本](src/train.py) 使用 Adam 和 MSE 损失，每批更新一次参数。新权重文件保存模型类型、模型结构参数、训练后的权重、输入特征顺序、标准化统计量和窗口长度。
- [评估脚本](src/evaluate.py) 按入口选择 RNN 或 LSTM，再从权重文件读取模型结构和预处理参数，按时间顺序遍历完整测试集一次。逐批累计每个窗口的误差，再汇总 MSE、MAE、RMSE 和最大绝对误差，最后一个不足批大小的批次也参与统计。
- MSE 使用 0–1 SOC 比例的平方误差。本文采用**SOC 百分点**表示 MAE、RMSE 和最大绝对误差，对应日志里乘以 100 后带 `%` 的数值。例如参考 SOC 为 80%、预测为 72%，绝对误差为 8 个百分点。

## RNN 调参过程

1. **建立 V1 基线。** 用 30 点窗口、单层 RNN 和隐藏维度 16 在 UDDS 上训练，权重转到 US06 评估后，MAE 为 8.85 个百分点。后续参数试验沿用这两个工况。
2. **把窗口拉长到 100 点。** V2 采用 100 点、单层和隐藏维度 16，US06 的 MAE 降到 3.09。过程中也试过批大小 16。同一份 V2 权重分别用评估批大小 16 和 32 运行，四项指标在日志的显示精度下一致。训练批大小会影响每轮的 Adam 更新次数。
3. **比较层数和隐藏维度。** 100 点窗口下，早期双层、隐藏维度 16 的试验得到 MSE 0.004613、MAE 5.18、RMSE 6.79、最大绝对误差 36.66。现有归档里的 V3 和 V4 是单层模型，分别把宽度改为 8 和 32。两版在 US06 上的平均误差都高于 V2。
4. **再比较其他窗口长度。** V5 使用 120 点窗口，V6 使用 80 点窗口。V5 的日志指标与归档复评有差异，见表后说明。以 US06 的 MAE 和 RMSE 为主要选型指标，最终采用 V2。

历史试验中批大小和训练轮数也有调整。下表保留日志中的批大小字段，模型结构和窗口长度另用归档权重核对。

## 最佳权重的复评结果

按 US06 的 MAE 选取各自最好的归档权重，即 [RNN V2](models/RNN/rnn_soc_2.pth)（100 点、1 层、隐藏维度 16）和 [LSTM V6](models/lstm/lstm_soc_6.pth)（300 点、2 层、隐藏维度 64）。两种模型都从每份数据的第 300 个采样点开始比较，确保预测对应同一批参考 SOC。上方日志表按每种窗口长度的全部有效时间点统计。

### 结论

1. **RNN V2 在 US06 上的平均误差更低。** LSTM V6 在参考 SOC 达到 25% 及以上时平均低估 **5.32 个百分点**，拉高了整体 MAE。低于 25% 时，LSTM V6 的 MAE 为 **2.67**，RNN V2 为 **5.64**。LSTM V6 在 US06 上的单点最大误差也更小。
2. **延长窗口改善了当前 LSTM 的 US06 表现。** V4 至 V6 同为 2 层、隐藏维度 64，窗口从 150、200 增到 300 点，MAE 从 11.66、7.28 降到 4.96。使用 150 点窗口时，隐藏维度从 32 增到 64 的记录中，US06 MAE 从 9.41 升到 11.66。这组试验里，增加历史长度比单独加宽隐藏层更有效。
3. **选型取决于工况和评价指标。** 以 US06 的 MAE 和 RMSE 为主时，RNN V2 是当前基线，也只需要 100 点历史和 353 个可训练参数。LSTM V6 使用 300 点历史和 51,009 个参数，在 LA92、低 SOC 区间和 US06 的最大绝对误差上表现更好。

两组试验都使用了 US06 来比较和选择配置，因此 US06 的结果反映的是这批归档权重在该工况上的表现。若要比较两种架构本身，需要统一训练预算，使用多个随机种子，并保留未参与选型的工况用于最终测试。

## 复现方法

复评使用了 Conda 的 `soc` 环境，版本为 Python 3.9.25、PyTorch 2.1.2、pandas 2.3.3、SciPy 1.13.1 和 tqdm 4.67.3。当前训练入口默认使用 CUDA，评估入口自动选择可用的 CUDA 或 CPU。

在 VS Code 中选用 `soc` 解释器，打开 [评估脚本](src/evaluate.py)。在入口处设置 `model_class`，并在 `checkpoint_paths` 中指定对应归档权重，再点击「运行 Python 文件」。

```python
model_class = LSTM  # 评估 RNN 时改为 RNN
checkpoint_paths = {
    LSTM: MODELS_DIR / "lstm" / "lstm_soc_6.pth",
    RNN: MODELS_DIR / "RNN" / "rnn_soc_2.pth",
}
```

脚本使用权重中保存的模型参数、标准化统计量和窗口长度。默认评估 US06，评估 LA92 时将 `test_path` 中的文件名改为数据表中的 LA92 文件名。

默认运行会统计该模型的全部有效窗口。复现上方对齐表时，在创建 `test_dataset` 后加入以下代码，使两种模型从第 300 个采样点开始统计。

```python
from torch.utils.data import Subset

offset = 300 - checkpoint["win_size"]
test_dataset = Subset(test_dataset, range(offset, len(test_dataset)))
```

重新训练时，在 [配置文件](src/config.py) 中设置窗口长度、隐藏维度和层数，在 [训练脚本](src/train.py) 中选择模型、设置批大小及轮数，并为新权重指定独立的保存路径。配置后在 VS Code 中运行 `train.py`。
