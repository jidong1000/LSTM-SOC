# 基于 RNN 的锂电池 SOC 估计

本项目用电压、电流和电池温度估计 Panasonic 18650PF 电芯的荷电状态（SOC）。这次完成了从 MATLAB 数据读取、参考 SOC 计算、滑动窗口训练到独立脚本评估的流程，并在 25 ℃ 下比较了不同窗口长度、RNN 层数、隐藏维度和批大小。

当前采用 **V2（100 点窗口、单层 RNN、隐藏维度 16）**。该权重在 US06 上的 MAE 为 **3.09 个百分点**，在 LA92 上为 **1.28 个百分点**。完整调参指标见下方汇总及 [原始日志](logs/)。

## 数据与预处理

| 用途 | 25 ℃ 工况 | 原始文件 |
| --- | --- | --- |
| 训练 | UDDS | `03-21-17_00.29 25degC_UDDS_Pan18650PF.mat` |
| 参数比较 | US06 | `03-20-17_01.43 25degC_US06_Pan18650PF.mat` |
| V2 的额外工况复评 | LA92 | `03-21-17_09.38 25degC_LA92_Pan18650PF.mat` |

原始数据由 Phillip Kollmeyer 发布。将解压后的数据放入项目根目录的 `datasets/`，脚本会按文件名递归查找相应的 `.mat` 文件。该目录通过 `.gitignore` 管理，克隆项目后需要另行准备数据。 [Panasonic 18650PF 原始数据集](https://data.mendeley.com/datasets/wykht8y7tg/1)

1. **读取数据和计算参考 SOC。** 从 `.mat` 的 `meas` 读取 `Time`、`Voltage`、`Current`、`Battery_Temp_degC` 和 `Ah`，去掉重复行。假设文件开始时为满电，按 `SOC(t) = 1 + (Ah(t) - Ah(0)) / 2.9` 计算标签，配置容量为 `2.9 Ah`。例如 US06 的 `Ah` 从 `0` 变到 `-2.58596`，按这个口径末尾 SOC 约为 `10.83%`。
2. **标准化输入。** 按电压、电流、温度的顺序组织三列特征，并使用 UDDS 的均值和标准差做 Z-score 标准化。评估时从权重文件读取这组统计量，用于处理 US06 或 LA92。SOC 标签以 0–1 比例参与计算。
3. **构造滑动窗口。** 每次向后移动一个采样点。去重后有 `N` 个采样点时，长度为 `W` 的完整窗口共有 `N - W + 1` 个。采样间隔约为 0.1 秒，所以 30 点约覆盖 3 秒，100 点约覆盖 10 秒。 [数据加载与窗口构造](src/dataset.py)

## 训练与评估

[模型定义](src/model.py) 使用 PyTorch 的 `nn.RNN`，再用全连接层把每个时间步的隐藏状态映射为一个 SOC 预测。训练与评估都取**窗口最后一个时间点**的 SOC，与同一时刻的参考值比较。

- [训练脚本](src/train.py) 使用 Adam 和 MSE 损失，每批更新一次参数。权重文件保存模型结构参数、训练后的权重、输入特征顺序、标准化统计量和窗口长度。
- [评估脚本](src/evaluate.py) 从权重文件恢复模型和预处理参数，按时间顺序遍历完整测试集一次。逐批累计每个窗口的误差，再汇总 MSE、MAE、RMSE 和最大绝对误差，最后一个不足批大小的批次也参与统计。
- MSE 使用 0–1 SOC 比例的平方误差。本文采用**SOC 百分点**表示 MAE、RMSE 和最大绝对误差，对应日志里乘以 100 后带 `%` 的数值。例如参考 SOC 为 80%、预测为 72%，绝对误差为 8 个百分点。

## 调参过程

1. **建立 V1 基线。** 用 30 点窗口、单层 RNN 和隐藏维度 16 在 UDDS 上训练，权重转到 US06 评估后，MAE 为 8.85 个百分点。后续参数试验沿用这两个工况。
2. **把窗口拉长到 100 点。** V2 采用 100 点、单层和隐藏维度 16，US06 的 MAE 降到 3.09。过程中也试过批大小 16。同一份 V2 权重分别用评估批大小 16 和 32 运行，四项指标在日志的显示精度下一致。训练批大小会影响每轮的 Adam 更新次数。
3. **比较层数和隐藏维度。** 100 点窗口下，早期双层、隐藏维度 16 的试验得到 MSE 0.004613、MAE 5.18、RMSE 6.79、最大绝对误差 36.66。现有归档里的 V3 和 V4 是单层模型，分别把宽度改为 8 和 32。两版在 US06 上的平均误差都高于 V2。
4. **再比较其他窗口长度。** V5 日志记录了 150 点试验，V6 对应 80 点。当前 V5 归档权重的窗口长度是 120 点，具体差异见表后说明。以 US06 的 MAE 和 RMSE 为主要选型指标，最终采用 V2。

历史试验中批大小和训练轮数也有调整。下表保留日志中的批大小字段，模型结构和窗口长度另用归档权重核对。

## 复现方法

复评使用了 Conda 的 `soc` 环境，版本为 Python 3.9.25、PyTorch 2.1.2、pandas 2.3.3、SciPy 1.13.1 和 tqdm 4.67.3。当前训练入口默认使用 CUDA，评估入口自动选择可用的 CUDA 或 CPU。

归档权重已放入 `models/RNN/`。运行前，在 [评估脚本](src/evaluate.py) 的 `torch.load()` 中将权重路径设为下面的位置。

```python
ROOT_DIR / "models" / "RNN" / "rnn_soc_2.pth"
```

然后在项目根目录的 PowerShell 中执行。

```powershell
conda activate soc
python .\src\evaluate.py
```

脚本默认评估 US06。评估 LA92 时，把脚本内的测试文件名改为数据表中的 LA92 文件名。评估其他版本时，只需选择对应归档权重，脚本会恢复其中的窗口长度和模型结构。

重新训练时，在 [训练脚本](src/train.py) 中设置窗口长度、隐藏维度、层数、批大小和轮数，并给新权重指定独立的保存路径。配置完成后，从项目根目录执行 `python .\src\train.py`。
